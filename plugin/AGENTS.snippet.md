# 委派式交付（常驻片段）

以下规则适合并入**项目级** `AGENTS.md`；如果希望所有项目生效，再并入用户级 `AGENTS.md`。

- 非平凡任务先明确目标、约束、验收标准和下一步；简单问答直接回答。
- ≥2 个无共享状态的任务，在同一条消息里并发派发；一次派发只做一件内聚的事。
- 给子代理喂目标、文件范围、验收命令和汇报格式；歧义在派发前消掉，禁止"顺便"扩范围。
- 写代码的子代理必须有自己的 worktree 和分支；只读子代理免隔离。
- 子代理返回四件：分支+commit、验证命令与退出码、改动文件+漏改清单、存疑点。
- 主代理亲手看 diff、跑全量门禁且连跑 ≥2 次；跨进程/协议/生命周期加端到端"先 A 后 B"序列。
- 写并发 2–3、只读 4–6 是上限；并发共用端口/状态必须隔离。
- 临时脚本和探针放在会话临时目录，结束前清理；报告区分"已验证的事实"和"未验证的推断"。
