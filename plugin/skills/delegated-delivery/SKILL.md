# 委派式交付

把“拆、派、验、合”做成可复用流程。适用于 ≥2 个无共享状态的任务、上下文密集的只读调查、需要并行推进的多步编码。一个直接回答或一条命令能解决的事，不要用本流程。

## 1. 派发判据

派子代理只问一个问题：**它会不会吃掉主代理的上下文，或者能不能与别的任务并行？**

派：

- ≥2 个互不共享状态的任务（同一条消息里并发派发）。
- 要通读大文件、翻多处、跑长链路、最终只产出一段结论的只读工作。
- 边界清晰、验收标准可写的机械性实现。

不派：

- 一条 `grep` / 一次 `git log` 就能答。
- 失败之间有耦合，修一个可能顺带修掉另一个。
- 还看不出坏在哪的探索性排障。
- 子代理之间会踩同一份状态（先隔离再派）。
- 改动集中在“1 个函数 + 1 个测试文件”，切割与交代的成本高于收益。

## 2. 切片与提示词

一次派发只做**一件内聚的事**：一个有明确验收标准的改动，或一份结论。

给子代理的提示词必须包含：

- 目标与背景（根因、算法、要改的行、期望值——主代理已查清的，直接喂进去）。
- 可动的文件范围，以及“不要动 X”。
- 验收命令与期望结果。
- 汇报格式（见第 4 节）。

禁止“顺便”：发现别的需要改，记进漏改清单交回来，不扩范围。
需求侧的歧义在派发**之前**消掉，不要指望子代理在执行中自己判断。

## 3. worktree 隔离

写代码的子代理必须有自己的 worktree：

```bash
git worktree add .worktrees/<slug> -b <feat|fix|docs|test>/<slug>
```

- 一个子代理 = 一个 worktree + 一个分支，它只许动这条分支。
- 只读子代理免隔离，不建分支、不许写。
- 开 worktree 前 `git status` 必须干净。
- 收尾：`git worktree remove .worktrees/<slug>` + `git branch -d <分支>`。

子代理不许 `merge`、`push`、删别人的分支/worktree、改主分支。集成权只在主代理。

## 4. 汇报契约

子代理返回固定四件，缺一件算没做完：

1. 分支名 + commit hash。
2. 跑过的验证命令与结果（含退出码）。
3. 改动了哪些文件，**以及没改但同属该任务的地方**（漏改清单）。
4. 未做/存疑/需要复核的点（没有也要写“无”）。

## 5. 主代理验收

1. 逐个 `git diff <主分支>..<分支>`，对照第 3、4 条核。
2. 跑项目自己的全量门禁；宣布完成前的最后一次必须是全量，并**连跑 ≥2 次**排除间歇性。单包/单测绿不等于全量绿。
3. 动了跨进程、协议、状态生命周期的，**端到端必须亲手跑**，专门构造“同一实例先 A 后 B”的序列；单元测试证明不了两次调用之间状态是干净的。
4. 合并用 `git merge --no-ff`。冲突退回子代理在它的 worktree 里重解。
5. 收尾确认 `git status` 干净、`git worktree list` 只剩主工作树。

## 6. 并发与环境隔离

- 只读子代理可并行 4–6 个；写子代理并发 2–3 个（同一套测试二进制会顶满 CPU）。
- 并发跑的测试/冒烟/手工实测必须隔离共享资源（端口、临时端点、配置目录）；否则并行线会互停、互抢。
- 计时与性能测试串行跑；不要用 shell 管道量单条命令耗时（会等整条管道）。

## 7. 底线

- **不静默做错事**：不认识的参数/子命令一律非零退出，不得静默忽略。
- 改了行为就同步改文档；文档与实现不许对不上。
- 临时脚本、探针、日志放在会话临时目录，结束前清理；`git status` 必须干净。
- 报告区分“我亲手验证过的”和“尚未验证的推断”；没跑过的命令写“未跑”，不写“应该通过”。
