# 已知差异与限制

本文从 [winbash/README.md](README.md) 拆出,原样收录「已知差异与限制」整表,
连同测试覆盖档案(哪些差异有测试钉住、哪些只是弱覆盖)。
上手用法(快速开始、命令行参数、四层路由、会话级状态、性能口径)见 [README.md](README.md)。

与真 bash 相比的差异。**这些差异的回归测试不在一个文件里** —— 原先这句话写的是「全部有测试钉住,见 `internal/shell/corpus_test.go`」,那是不准确的(那张表有 31 条,而 `corpus_test.go` 里只有一个 Test 函数)。实际分布是这样:

- **`corpus_test.go` / `pbb_corpus_test.go` 是差分测试**(拿真 bash 的实际输出当参照)。它们的 `known:` 语料是**豁免说明** —— 「这几条差异存在,比对时跳过」。所以一条差异被列进 `known:`,只说明它被**承认**,不说明它被**钉住**。这两件事别混。
- 真正把行为写死的是各层专项测试:`classify_test.go`(printf/trap 类缺口)、`commandv_test.go`、`grep_test.go` + `grep_binary_test.go` + `grep_classes_test.go` + `grep_class_scanner_test.go` + `grep_switches_test.go`、`ls_test.go`、`cat_test.go`、`msyspath_e2e_test.go`、`msysargv_test.go`、`trapguard_test.go`、`oilspec_gaps_test.go`、`internal/winmgmt/pwshcmd_test.go`、`internal/daemon/guard_test.go` + `stdin_cwd_test.go` + `state_test.go` + `fresh_test.go` + `boundary_test.go` + `serve_test.go`、`cmd/winbash/e2e_test.go`。
  (`daemon` 包的专项测试是分三轮补的,每轮都用覆盖率数据定位、用变异验证鉴别力:第一轮 `stdin_cwd_test.go` 补 **stdin 流式转发**与 **cwd 切换**(原为 0%);第二轮 `state_test.go` 补**会话池记账与关停超时**;第三轮 `fresh_test.go` + `boundary_test.go` + `serve_test.go` 补 **`--fresh` 的四个隔离维度**、**协议边界**(未知 `stdin_mode` / 坏帧 / 队列满 / 具名会话上限)与 **`Serve`/`watchdog` 的参数边界**。该包总覆盖 **71.6% → 94.5%**,`handleConn` / `watchdog` / `statusText` / `entryStatusLocked` / `waitWorker` / `closeSessions` / `submit` / `tokenOK` / `shellQuote` / `rejectJob` 均达 100%。)
- 还有三条**刻意不测**的(写了就是不稳定测试):`pickSession` 里「锁外建 Session 期间 daemon 开始关停」与「别人抢先建了同名」两处竞态窗口 —— 只在极窄调度窗口命中,靠 sleep 碰运气必然 flaky,而注入 hook 会让生产代码为测试让步;`newToken` 的 `rand.Read` 失败分支同理(需注入随机源)。这三处靠 code review 保证。
- 另外三条**变异验证证明抓不住**的,已写在各测试的注释里(不是缺口,是等价/不可观测):`pickSession` 的**第一处** `stopping` 检查(去掉后第二处仍会兜住,功能等价,只是白建一个 Session 再关掉 —— 第一处是性能优化);`TestBadFrameDoesNotWedgeDaemon` 只验证「坏帧不拖垮 daemon」,不验证「坏帧必须有错误响应」(实现选择是不回,因为对端根本没在讲这个协议);`Serve` 里 `net.Listen` 失败与 `writeResponse` 的 Encode 失败属于实际不可达路径。
- 有 5 条只是**弱覆盖**(测试覆盖了相邻行为,但没有逐字钉住这条差异):显式 `Git\bin\bash.exe` 的第二跳吃引号、`grep -E 'a*?'` 的匹配数差异、`ls` 默认不列点文件、`grep -r` 的 `./` 前缀、`pwsh -c "$env:X"` 的空展开。改这些地方时不能指望测试变红。**这份清单是照测试注释与断言盘的,不是机器判定** —— 某个用例后来被加强了,这里就会偏保守(写"弱"而其实够强),不会反过来。
  (原先这里还有一条 `ls -l` 的四列;那一列已经补成 7 列,不再算"弱覆盖",见表格里对应的行。)

**原先完全没有测试钉住的 2 条,本轮已补上**:`cat -n` 的号码格式(`%6d<TAB>`、跨文件累加,见 `cat_test.go` 的 `TestCatNumberedUsesSixWideTabFormat` / `TestCatNumberedKeepsCountingAcrossFiles`,以及未实现开关要响亮拒绝的 `TestCatUnimplementedFlagsAreRejected`)与 `printf '%(%Y)T'`(strftime 报 `invalid format char` 且 exit 1,见 `classify_test.go` 的 `TestPrintfStrftimeFormatIsRejectedLoudly`)。补之前这两条是「文档承认、行为也对、但改坏不会变红」的状态。

| 现象 | 说明 |
|---|---|
| `pwd` 给 `D:\...` | 刻意:这一层的返回值要能直接喂给 Windows 工具(bash 给 `/d/...`)。**例外**:`cd /` 后 `pwd` 给 Git 安装根(真 bash 的 `/` 就是它) |
| glob 给 `.\x` | 同理,Windows 原生形式;①/②/③ 层两种写法都吃 |
| `${v/#前缀/替换}`、`${v/%后缀/替换}`、`${v~~}`(翻转大小写) | **不支持,报错 `2`**。前两个 mvdan/sh 没实现、会**静默原样输出**,我们拦下来报错;`${v~~}` 则连 parser 都不认(报 `not a valid parameter expansion operator`),天然响亮。真 bash 三条都正常 —— 实测 `${v~~}`:winbash rc=2、报 `not a valid …`,真 bash rc=0、输出翻转结果(`ABC`)。宁可报错(`pbb_corpus_test.go` 的「翻转大小写」「只替换开头」两条 known 语料记着) |
| `<(...)` / `>(...)` 进程替换 | **不支持,报错 `2`** —— 与上面几行同属「响亮报错好过静默」。报错是三行式(首行 `winbash: shell`,问题行点名「这台机器上不支持进程替换 <(命令)」,怎么办行给替代写法:改用临时文件),真 bash 则 rc=0、正常工作。**为什么必须拦**:不拦的话 mvdan/sh 会把一句 `TODO: support process substitution on Windows` **打到 stdout** —— 看起来像输出、实际是未实现标记,是最恶劣的失败形态;所以 winbash 在**解析之后、运行之前**走一遍 AST 拦掉(`internal/shell/shell.go` 的 `rejectProcessSubstitution`,回归 `classify_test.go` 的 `TestProcessSubstitutionIsRejectedBeforeRunning`) |
| `printf %q`、`printf -v` | 同上:不支持但显式报错,并给替代写法 |
| `command -v find` / `type find` | 这两个是 mvdan/sh 的内建,按进程 PATH 回答(给 System32 那个)。准确答案用 `which find`。**`command -v` 已被 guard 接管**:①/② 层内建与只在 Git Bash `usr\bin` 里的工具都答得对,**多名字也行**(`command -v ls cat`;`TestCommandVHandlesMultipleNames`)。一条残余缺口:**混合写法**会放行给 mvdan/sh —— 例如 `command -v ls git` 里 `ls` 仍被漏报(`git` 在进程 PATH 里、mvdan 自己答得对,而 `CallHandler` 只能返回一条命令,没法逐名字替换)。要逐个判存在就分开写:`command -v ls && command -v git`。`type -p` / `type -t` 与 `type find` 同待遇:**未接管**,按进程 PATH 回答。另:`which find` 给的是 **Windows 路径形式**(`C:\Program Files\Git\usr\bin\find.exe`),真 bash 的 `which` 给 MSYS 形式(如 `/usr/bin/find`)—— 指同一个文件,只是命名法不同(`corpus_test.go` 的 known 语料记着) |
| 显式写 `Git\bin\bash.exe` 时参数里的双引号 | 那个 47 KB 的 exe **不是 MSYS 程序**,是 Git for Windows 的原生 launcher(导入表只有 `KERNEL32`/`msvcrt`/`SHELL32`,没有 `msys-2.0.dll`)。它把命令行**转发**给 `usr\bin\bash.exe`,这一跳用 MSVC 规则重拼,参数里的 `"` 到真 bash 手里已经变成 `\` —— **不是我们的转义问题**:对原生目标用标准 MSVC 规则是对的,坏在第二跳不受我们控制。按 PATH 找 `bash`(`which bash` 给的就是 `usr\bin\bash.exe`)完全正常,只有显式写全路径到 `bin\` 才会撞上 |
| `set -u` / `${v:?}` | 退出码 `1`(bash 的 `-c` 给 `127`),错误文本不带 `bash: line N:` 前缀——都非零、都点名变量 |
| `cd` 的失败措辞 | **已修(2026-10-18)**,只剩路径形式这一处差异。现在给 `cd: <路径>: No such file or directory` / `Not a directory` / `Permission denied` / `null directory` / `too many arguments` / `OLDPWD not set`,与真 bash 逐条一致(修前是 `no such file or directory: "<带引号>"` 小写 + 把「不是目录」也说成「不存在」)。**剩余差异**:报错里的路径是 **Windows 绝对形式**(`cd: C:\Program Files\Git\x: …`),不是用户写的 `x`;根因是 `normalizeCdPath` 在参数进 interp 之前就改写了,而 interp 没有 API 带回原串 —— 这与 `pwd` 给 `D:\...` 是同一个既定设计。回归:`internal/shell/cdwording_test.go` |
| `cd` 到**无权限**目录 | Windows 上 `cd /c/Windows/System32/config` 会**成功**(rc=0),真 bash 报 `Permission denied`、rc=1。原因是 Windows 的 ACL 与 `AccessExec` 判定不把它当"不可进入"(同一目录 `test -x` 两边都返回真)。这是**平台权限模型差异**,不是措辞问题 —— 在 Windows 上普通用户确实能列这个目录 |
| `>&` / `<&` 重定向与 fd 编号 | **已修(2026-10-18)**:`echo x >& 99` / `2>&99` / `<& 99` 现在给 `99: Bad file descriptor`(真 bash 同),修前是 `unhandled >& arg: "99"`(露内部 token 名)。**剩余差异**:⓵ `>&bad`(非数字)真 bash **静默**按 `&>bad` 处理、创建文件、rc=0,我们报 `bad: Bad file descriptor` —— 按「不静默做错事」的底线,响亮更好;⓶ fd 3+ **已修(fd 表落地)**:`exec 3>&1` / `echo x >&3` / `echo foo 5>a` / `exec 4>f` 现在与真 bash 一致(见 `third_party/mvdan-sh/WINBASH-PATCH.md` §5,回归 `internal/shell/fdtable_test.go`)。**剩余边界**(明确不做):a) 传 fd 给外部命令 —— 子进程看不到 fd 3+(Windows 的 `cmd.ExtraFiles` 不支持),其中「命令自身带 fd 3+ 重定向」(`cmd 3>log`)**响亮报错** `cmd: fd 3 cannot be passed to external commands`、rc=1,而不是静默丢重定向;`exec 4>f; cmd` 不报错,cmd 看不到 fd 4(cmd 真要用 fd 4 时才有损);b) `test -t 3`、`read -u 3`、`{var}>` 动态分配、`/dev/fd/3` 路径不支持;c) 跨命令 fd 偏移/seek 语义不做;d) 标准流**反向重开**(`read 1</dev/null`、`exec 1<file`)按近似处理:fd 1/2 变成只读(写它报 `Bad file descriptor`,与真 bash 同),但**读** fd 1/2 做不到(我们的 stdio 槽只有写侧),输入内容不挂载;输出重定向落 fd 0(`0>file`)报 `unsupported redirect fd: 0`;e) dup 是单向的(`4>&3` 只复制写端、`4<&3` 只复制读端);f) `exec 3<&0` 跨 Run 失效(winbash 每次 Run 收尾换掉 stdin 管道,防 use-after-close,之后 `cat <&3` 给 `3: Bad file descriptor`),而 `exec 3>&1` 的 fd 3 写入跟随**当次** Run 的 stdout;⓷ `echo x >&-`(关闭 stdout)**已修**:现在写关闭的 stdout 会报 `echo: write error: Bad file descriptor`、rc=1(真 bash 同),`printf` / `pwd` 等内建同理,`cat f.txt >&-` 也跟着 rc=1(① 层内建的写错误自然传播);修前用 `io.Discard` 让写"成功"、rc=0、无报错(静默失败)。**关键区分**:这只对**显式关闭的 fd** 生效 —— 管道 broken pipe(`echo foo \| false \| true`)仍**静默**、rc=0,与真 bash 一致(那按 SIGPIPE 语义处理);两者对 `Write` 都返回 error,但语义不同,混为一谈会把正常管道变成噪音(`TestBrokenPipeIsSilentUnlikeClosedFd` 钉住)。**剩余边界**:`read x <&-`(关闭 stdin 那半边)本轮没动,仍靠 `read` 自身的 nil guard 报错返回 1 |
| 从目录重定向输入(`source adir` / `cat < adir` / `read < adir`) | **已修(2026-10-18)**,但有一条**语义差异要记住**。Windows 上 `os.Open` 一个目录会**成功**(`O_RDONLY`),失败要到第一次 Read 才发生 —— 所以修前这些报错带着 `Incorrect function.`、绝对路径,其中 `read` 甚至**完全静默**(只有 rc=1、一个字节的提示都没有),`mapfile` 则报 `mapfile: unable to read, read <绝对路径>: Incorrect function.`(Win32 长句 + 绝对路径,但至少有声音;`internal/builtins/dirread.go` 的修前记录为准)。现在在 open 阶段就判目录,统一给 `<你写的路径>: Is a directory`。**语义差异**:`read < 目录` / `mapfile < 目录` 在真 bash 里是 open 成功、失败在读(`read` 报错返回 1、脚本继续;`mapfile` 干脆静默 n=0),而我们是「重定向失败、命令不执行」—— `read` 那条脚本层面一致(都 rc=1、都不终止),`mapfile` 那条从「静默成功」变成「响亮失败」(按项目底线,响亮是更好的那边)。**剩余差异(措辞大小写)**:`source <目录>` 真 bash 给 `is a directory`(**小写** i),我们给 `Is a directory`(大写 I,与 `cat < 目录` 一致;`readerr_test.go` 的注释明记这条)。回归:`internal/shell/readerr_test.go` |
| 脚本报错里的文件名 | **已修**:`./script.sh` 执行出错时,报错前缀用**用户写的原串**(`./script.sh: line 1: foo: command not found`),与真 bash 一致;修前给解析出的绝对路径(`C:/Users/…/script.sh: line 1: …`)。**归因改正**:这不是 mvdan/sh 干的 —— 那条 `line N:` 报错是 MSYS 的 bash **子进程**生成的,bash 的运行时报错前缀用 `$0`,而 `$0` 正是 winbash 传给 `env.exe` 的脚本参数,原先传的是绝对路径,现已改传用户写的原串(`runExternal` 里 ResolveShellPath 未改写原串时)。**剩余边界**:报错仍给绝对路径的有两类写法 —— ⓵ POSIX 挂载路径(`/tmp/x.sh`、`/c/x/y.sh`):winbash 的合成挂载与 bash 自己的 MSYS 挂载表可能分叉,传原串反而有指到别的文件的风险,故刻意保留绝对路径;⓶ 裸名字(`./x.sh` 之外经 PATH 解析的脚本,如 `probe-script`):原串要靠 bash 子进程自己搜 PATH,而它拿到的是 winbash 合成的 searchPath,搜索语义可能与定位时不同。相对路径写法(`./script.sh`、`sub/x.sh`)与盘符写法(`C:/x/y.sh`)都给用户写的原串。回归:`internal/shell/scriptname_test.go` |
| `${#关联数组[@]}` | mvdan/sh 的缺口:恒返回 `1`(键列表 `${!m[@]}` 与取值都是对的) |
| 关联数组的**迭代顺序** | **静默差异**:winbash 按**插入序**遍历(`${!m[@]}` / `for k in …`),真 bash 是**哈希序** —— 两边都 rc=0、都不报错,只有顺序不同。依赖顺序的脚本本来就不该写;`corpus_test.go` 的语料因此只查「键值都在、取得出」,**不比顺序** |
| `IFS` 给**多字符** | mvdan/sh 把整个串当分隔符,真 bash 只取**第一个字符**(`IFS=BC` 等价 `IFS=B`)。**静默**差异,光看输出看不出对错 —— 要按多字符分,请用 `IFS=,` 这类单字符,或先 `tr` 转换 |
| **管道段不是真子 shell** | **静默差异**(两边都 `exit 0`、都不报错,只有输出不同):`cmd \| <右侧>` 右侧对变量的赋值会**泄漏到外层**,而真 bash 里右侧是独立进程、赋值随进程消失。实测三种形态都泄漏:`printf "a\nb" \| while read -r _; do n=$((n+1)); done` 之后 `n=2`(真 bash 得 `n=0`);`echo x \| f` 里函数内的赋值;`echo x \| { export PX=1; }` 的 `export`。**根因是上游架构限制,不是本项目的 bug** —— mvdan/sh 的 README 明说 `Go does not support forking its own process, so subshells use a goroutine instead`,管道每段是一个 goroutine 而非进程,变量绑定因此共享作用域。**这一条的方向对 AI 干活有利**(`n=2` 才是直觉预期),要防的是它无声变掉;`oilspec_gaps_test.go` 的 `TestPipelineSegmentsAreNotRealSubshells` 同时钉住三件事:泄漏的三种形态、显式 `( )` / `$( )` / `{ }` 与 bash 一致的隔离(防止有人"修"泄漏时把对的也改坏)、以及推荐替代写法 `while ... done < file`(`TestRedirectWhileDoesNotLeak`) |
| `printf '%.0s'` 这类带**精度**的格式 | mvdan/sh 的内建 printf 不认 `%.0s`(`.0` 是**精度**、不是宽度),打 `invalid format char`、**退出码 1** —— 而真 bash 是 rc=0、无 stderr(它把 `printf '=%.0s' 1 2 3` 这类零精度写法当合法技巧用)。方向是**我们更严格、我们报错**,不是静默错值;同机制的 `printf '%(%Y)T'` 见本表 strftime 那行(同为退出码 1)。实现依据:interp 的 printf format 错误一律 `failf(1, …)`(`third_party/mvdan-sh/interp/builtin.go`),上游测试期望也是 `exit status 1`(`interp/interp_test.go`)。靠退出码判断成败的调用方要当心:真 bash 下 rc=0 的写法,在我们这里会失败(`pbb_corpus_test.go` 的「printf 重复字符」语料记着同一条) |
| `grep` 遇到含 NUL 的文件 | **输出策略与真 grep 不同**:真 grep 一旦看到 NUL 就切二进制模式,只打一行 `Binary file X matches`;我们**保持逐行输出**(这样 `-c` 的计数与行号都可复现 —— 真 grep 在二进制模式下 `-c` 会给出另一个数),但匹配行里含 NUL 时**往 stderr 说一句**,不静默。`-l` / `-q` 不吐内容,不提示 |
| `grep -E '\d'`、`(?i)` | 真 bash **静默**按字面处理(`\d` 退化成 `d`);我们**明确拒收**并给 POSIX 替代 |
| `grep '\d'`(无 `-E`) | 默认方言是 BRE,元字符与真 grep 一致;但 `\` 后跟**普通字符**时我们按**字面**处理(`grep '\d'` 只匹配 `\d` 这两个字符),而 GNU grep 会忽略反斜杠、连 `d` 一起匹配。刻意如此:不让"没匹配"被误读成 Perl 简写生效了 |
