## 一、逐条核验

核验方式:重建二进制,用**一字符一行**的语料(匹配结果本身就是字符集合),winbash 与
真 Git Bash 各跑一遍,逐字节比对。

```
语料 chars.txt 内容(每行一个字符):\  d  ]  a  z  -  b  w  [  ^  0  5
命令: winbash -c "grep -E '<pattern>' chars.txt"  vs  真 Git Bash 同样命令
```

| pattern | 复审的说法 | 实测 winbash | 实测真 Git Bash | 判定 |
|---|---|---|---|---|
| `[\d]` | 真 grep 给 `d` | `\` `d` | `\` `d` | 复审**错**,两边一致 |
| `[\w]` | 真 grep 给 `w` | `\` `w` | `\` `w` | 复审**错**,两边一致 |
| `[a\-z]` | 有假阳性 | `\ d ] a z b w` | `\ d ] a z b w` | 复审**错**,逐字相同 |
| `[\-a]` | 有假阳性 | `\ ] a` | `\ ] a` | 复审**错**,逐字相同 |
| `[\[]` | 有假阳性 | `\ [` | `\ [` | 复审**错**,逐字相同 |
| `[\]]` | 真 grep 给 `]` | 无匹配(exit 1) | 无匹配(exit 1) | 复审**错**,两边一致 |
| **`[\\d]`** | 编译失败 | **报 invalid escape sequence(exit 2)** | `\` `d`(exit 0) | ✅ **成立** |
| **`[\\]`** | 静默无匹配 | **报 missing closing ](exit 2)** | `\`(exit 0) | ✅ **成立** |

### 1.1 复审在 `[\d]` 这一条上把自己的方法论用反了

它说"真 GNU grep 把类内的 `\` 当转义引导符,`\d` 退化成 `d`" —— 如果这是真的,那么
`echo '\' | grep -E '[\d]'` 在真 bash 里应该**不**匹配。实测**匹配**:

```
$ printf '\\\nd\n' | grep -E '[\d]'      # 真 Git Bash
\
d
```

两边都匹配 `\` 与 `d`,也就是说真 grep 把类内单个 `\` 当**普通字符** —— 与 POSIX ERE 的
字面规定一致,也与 winbash 的归一化方向一致。**归一化的方向从一开始就是对的。**

### 1.2 但根因说得对,这正是它的价值

`[\\d]` 与 `[\\]` 都是同一个错误:**对已经转义的 `\\` 又转义了一次**。它用"前后对照"的手法
定位到这一点,方向准确。它建议的修法("与 `firstPerlClass` 共用同一段状态机")也采纳了(见 §三)。

### 1.3 已修(3 条真回归)

| 问题 | 修前(实测) | 修后(实测) | 真 bash |
|---|---|---|---|
| `grep -E '[\\d]'` | 报错 exit 2 | 匹配 `\` `d` | 匹配 `\` `d` ✅ |
| `grep -E '[\\]'` | 报错 exit 2 | 匹配 `\` | 匹配 `\` ✅ |
| `cat -n f1 f2` | `1 2 1 2` | `1 2 3 4` | `1 2 3 4` ✅ |
| `ls -a`(目录含 `!x`) | `. .. !x .hidden …` | `!x . .. .hidden …` | `!x . .. .hidden …` ✅ |

回归对照(`ls` 不带 `-a`、`ls -1`、`cat -n` 单文件)逐字未变。

## 二、复审里**不成立**的两条断言

### 2.1 "语料 oracle 被 `BASH_ENV` / `BASH_FUNC_*` 污染,`go test ./...` 是红的"

本机实测:

```
BASH_ENV      = (空)
BASH_FUNC_*   = 0 个
真 bash type rm = rm is /usr/bin/rm
go test ./...  → 10 包全绿
```

复审描述的垫片在这台机器上**不存在**。它很可能是被它自己的沙箱环境注入的 —— 但**它的加固建议
本身是好的**,所以采纳了(见 §三.3):参照子进程现在拿一份显式环境,滤掉 `BASH_ENV`、`ENV`
与所有 `BASH_FUNC_*`。理由与它写的一致:差分测试的价值完全取决于参照物可信,而这类红**在干净
机器上复现不了**,失败信息还会把人引向"winbash 的 `rm` 不对"。

### 2.2 "`client` 覆盖率 28% → 7.8%"

这是**包内口径**的数字,没错,但据此得出"新增函数没有测试"是错的。表现同一批代码的两种口径:

| 函数 | 包内口径 | 跨包口径(`-coverpkg=./...`) |
|---|---|---|
| `oneShot` | 0.0% | 58.6% |
| `isTimeout` | 0.0% | 100% |
| `pwsh.Dead` | 0.0% | 100% |

`guard_test.go` 从 `daemon` 包那一侧跑完整往返,所以它们是**被测过**的,只是在 `client` 包
自己的覆盖率里不计数。复审自己也写了"不能据此说修复没被测试",但它在 §5 的修复清单里仍是
按"覆盖率掉了"的措辞列的。

不过它点名的两个真·零覆盖函数(`readEndpoint`、`forgetStaleEndpoint`)确实该补 —— 已补,
`client` 包内覆盖率 **7.8% → 20.7%**。

## 三、已落地的改动

1. **`grep -E` 字符类归一化的两个边界**(保留归一化,补边界,而不是撤回归一化)
   - 成对消费 `\\`:已经转义的转义不再处理。
   - `[` 或 `[^` **紧跟**的 `]` 按字面量处理(与 `firstPerlClass` 同一套规则 —— 采纳复审
     的可维护性意见:一个包里不该有两份规则不同的字符类状态机)。
2. **`cat -n` 行号跨文件累加**;**`ls -a` 的 `.`/`..` 参与统一排序**。
3. **语料 oracle 的显式环境**(滤 `BASH_ENV` / `ENV` / `BASH_FUNC_*`)。
4. **`client` 的 `readEndpoint` / `forgetStaleEndpoint` 单测**(5 个用例,覆盖两行解析、
   缺 token 的降级、空文件、地址匹配才删、不匹配不删、文件不存在)。
5. **复审 P3 的四处**(都是一个函数级):
   `--timeout` 在嵌套里静默失效 → 建 ctx;`writeResponse` 无写超时 → `SetWriteDeadline`;
   `sanitizeCell` 每格无条件跑正则 → 先扫一次 `0x1b`;`copyCat` 里重复包了一层 `SafeStdin`。

### 3.1 新增的防回归机制(本轮重点)

复审的方法论正确,**期望值不能手写**这一点尤其正确。落成两份 golden 表:

| 表 | 内容 | 生成方式 |
|---|---|---|
| `internal/builtins/testdata/grep-e-classes.jsonl` | 8 个字符类 pattern | `go test ./internal/builtins/ -update-grep-golden` |
| `internal/shell/testdata/pbb-corpus.jsonl` | 37 条 pure-bash-bible 用法 | `go test ./internal/shell/ -update-pbb-corpus` |

两份都由**真 Git Bash**产出,不手写;常规测试只读盘比对,不需要装 Git Bash。

为什么这一条比百分比重要:字符类归一化的两种坏表现**都是哑的** —— 一种像"你的模式写错了"
(exit 2),一种像"真的没有东西匹配"(exit 1)。8 个 pattern 里当初 6 条一致、2 条回归,
**行覆盖率在这里完全没提示**。

## 四、pure-bash-bible 语料的收获

按 `https://github.com/dylanaraps/pure-bash-bible` 的招牌技巧建了 37 条语料
(参数扩展、数组、IFS、间接引用、路径操作)。**32 条本来就一致**,5 条差异——全是 `mvdan/sh`
的缺口,按语料既有约定标成 `known`(并且断言"差异仍然存在",哪天变一致了会失败提醒删除):

| 用例 | winbash | 真 bash | 性质 |
|---|---|---|---|
| `${v~~}` 翻转大小写 | 报错 exit 2 | `hEllO` | **响亮报错**,可接受 |
| `${v/#pat/rep}` | 报错 exit 2 | `Xaa` | **响亮报错**,可接受 |
| `IFS="BC"` 多字符 | `a\|b\|c` | `a\|\|b` | ⚠️ **静默**给出不同结果 |
| `printf '=%.0s'` | 无输出,**exit 0** | `=====` | ⚠️ 有 stderr 但退出码不非零 |
| `${#m[@]}` 关联数组长度 | `1` | `2` | 已知(README 原有) |

两条"响亮报错"符合项目底线(不静默做错事),不必修。另外两条值得单独记住:

- **`IFS` 多字符**:真 bash 只取**第一个字符**(`IFS=BC` 等价 `IFS=B`),`mvdan/sh` 把整个串
  当分隔符。这是**静默**的语义差异,只看输出看不出对错。已记进 README 已知差异表。
- **`printf '%.0s'`**:这是整份语料里唯一"打了 stderr 但**退出码仍是 0**"的一条 ——
  对"靠退出码判断成败"的调用方(以及 AI)来说,这是最需要盯住的形态。也已记进 README。

## 五、未采纳的建议

| 复审建议 | 决定 | 理由 |
|---|---|---|
| "撤回归一化,回到类内带 `\` 一律报错"(乙方案) | **不采纳** | 归一化方向经实测是对的(§1.1);撤掉会把 6 个本来正确的 pattern 一起退回"报错",是**扩大**差异而不是缩小 |
| "真 grep 把 `[\d]` 当 `d`" | **不采纳** | 实测真 grep 给 `\` 与 `d`(§1.1),据此改会**引入**不一致 |
| `grep -r` 应跳过 `.git` | 早前已不采纳 | 真 bash 的 `grep -r` 也不跳(跳的是 `git grep`) |
| 加协议版本号 | **记账,不做** | 目前靠"字段可选 + 缺凭据拒绝"兜住;等真要改帧格式时再上 |
| daemon stderr 重定向到文件 | **记账,不做** | 意见合理,但要先决定日志位置/轮转策略,不在本轮 |
| CI 配置 | **受结构限制** | 仓库是 `git subtree split -P winbash` 拆出来的,根目录只有 `winbash/`,而 GitHub 只认仓库根的 `.github/` |

## 六、对复审方法本身的两点意见

1. **"按规范推理"与"按参照实现实测"冲突时,它选了推理,而且没有跑一遍就下结论。** §1.1 那条
   它写的是"实测 `grep -E '[\d]'` 在真 bash 里匹配 `d`" —— 但真跑一次就能看到它还匹配 `\`。
   在一个以"与参照实现对齐"为卖点的项目里,这条尤其重要。
2. **它的"前后对照"手法是对的,而且一次就抓到了 `[\\d]` / `[\\]` 这个真根因。** 这是本次复审里
   质量最高的一段,值得保留成常规做法 —— 本轮的 golden 表就是它的固化形式。
