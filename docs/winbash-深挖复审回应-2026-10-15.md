## 二、修法与"修复会不会引起影响"

### 2.1 `--idle` 转发

**它的诊断完全正确**:机制本身没问题,丢的是转发。修法是把 `idle` 一路传下去
(`spawnDaemon` → `ensureDaemon` → `dialAddr` → `dial` → `oneShot` → `retryAfterAuthFailure`)。

**两处需要小心的地方**:

1. **`idle<=0` 不能直接拼进 argv。** `--idle 0` 在 daemon 侧是"永不退出",那是**另一个意思**,
   不是"没指定"。所以只有 `idle > 0` 才拼。
2. **默认行为不能被改变。** 对照验证:`winbash -c 'echo start'`(不给 `--idle`)等 5s 后
   daemon 仍在、端口文件仍在 —— 与修前一致。

**附带补了一个真缺口**:原先把参数拼在 `spawnDaemon` 里,而它必须构建真可执行文件才跑得起来
(测试进程里 `os.Executable()` 是 `winbash.test`,它不认识 `--serve`),所以"参数有没有拼对"
这一环**完全没有回归网** —— 这正是它能静默失效这么久的原因。现在抽成纯函数 `serveArgs()`
并加了测试。

### 2.2 `looksLikeMissingPath` 大小写

一行 `strings.ToLower`。**顺带把 `errs` 覆盖率从 57.1% 拉到 100%** —— 补的正是它点名的四个
零覆盖函数(`hasPosixPathArg` / `hasSingleSlashFlag` / `looksLikeMissingPath` / `isLetter`)。

**写测试时发现一处洞见,值得记下来**:`/c/nope` 同时满足两个判定 —— 它是盘符路径,**也**满足
"斜杠+字母"开头。但两个分支其实**不靠参数形状区分**,而靠**输出特征**:

| 参数 | 工具怎么理解 | 报什么 |
|---|---|---|
| `/c/nope` | 字面目录 `/c/nope` | `no such file` |
| `/v` | 被 MSYS 改写 | `Invalid syntax` |

所以词法重叠**不会**误判 —— 前提是两者的 raw 特征保持互斥。这条已经钉进测试;哪天有人把
单斜杠开关的条件放宽(例如只看 `cannot` 就算),会立刻失败。

### 2.3 `grep` 的二进制策略(用户选定:只提示,不对齐 GNU)

**不对齐 GNU 的理由不是省事**,而是两条实测:

1. 真 grep 切二进制模式后 **`-c` 的计数语义会变** —— 那是个更难解释的差异,会连累
   `grep -c` 这个最常用的统计写法。
2. "哪个 buffer 里先看到 NUL" 是 **libc 内部策略**:实测一个 45KB 的文件,前 40000 字节
   是纯文本匹配行、后面才有 NUL,GNU 照样判它 binary。依赖那个边界等于给一个
   "像 GNU 但边界不同"的假预期。

**折中**:输出不动(规则可解释、行号与 `-c` 可复现),但**不再静默** —— 匹配行含 NUL
时往 stderr 说一句。

**判据的边界**(这是最需要想清楚的一处):判据是"**被输出的**行含 NUL",不是"文件里有 NUL"。
后者会让一个 100MB 的日志因为某一行乱码而**每次** grep 都多一句噪声。三种情形都钉住了:

- 匹配行含 NUL → 提示;NUL 出现在**没被输出**的行 → 不提示;纯文本 → 不提示
- `-v` 反转后含 NUL 的行**成为**输出 → 仍然提示(判据是"被输出"而不是"匹配")
- `-l` / `-q` 不吐内容 → 不提示(它们靠退出码与 stdout,不该被 stderr 打扰)

README 的「已知差异」表已记上这一条。

## 三、§2.4 为什么不改

复审观察到 1 个 pwsh 孤儿并且**自己标记了"无法重现"**,建议在 `--status` 里带上引擎 pid
"这样孤儿是否由某个 daemon 留下就一眼可查"。

实测 `winbash --status` 的输出是:

```
pid=11252
cwd=D:\work\中文 目录\winbash
addr=127.0.0.1:56162
pwsh=pid=19812 calls=2      ← 已经带了
```

所以这条建议的前提不成立,不需要改。但**它的意图是对的** —— 那种"父进程已死、pwsh 还活着"
的孤儿确实值得能一眼查。真出现时,`--status` 的 `pwsh=pid=` 与系统进程表对照即可定位。
