# winbash Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 做一个 bash 语法 + pwsh 能力的常驻 shell `winbash`,让 AI 在 Windows 上不再因为猜错环境而翻车。

**Architecture:** `winbash -c '…'` 是一个轻客户端(~15ms),通过 TCP loopback 连常驻 daemon(传输层决策见 Task 2 Step 4)。daemon 进程内用 `mvdan.cc/sh/v3` 的 `interp` 执行 bash 语义,每条命令过 `ExecHandler` 按四层路由:① 纯 Go 内建 → ② Go 内建(底层转常驻 pwsh 子进程) → ③ 真实 PATH(含 Git Bash 的 `usr\bin`) → ④ 可操作的报错。

**Tech Stack:** Go 1.26 · `mvdan.cc/sh/v3` v3.14.1(唯一**直接**依赖;实测会带入 `golang.org/x/sys`、`golang.org/x/term` 两个间接依赖)· TCP loopback(见 Task 2 Step 4)· PowerShell 7.6.3(被 embed 的脚本驱动)

**Spec:** `docs/superpowers/specs/2026-10-13-winbash-design.md`

## Global Constraints

- 平台:Windows 11。只在 Windows 上验证。
- Go 单二进制;**唯一直接依赖** `mvdan.cc/sh/v3`(v3.14.1),不引入其他直接依赖。
  实测它会带入两个间接依赖:`golang.org/x/sys` 与 `golang.org/x/term`(后者是因为 `interp` 支持交互模式)。
  若 `go build` 报 `missing go.sum entry for golang.org/x/term`,执行 `go mod tidy` 即可 —— **不要为此改架构**。
- **依赖镜像必须设 `GOPROXY=https://goproxy.cn,direct`** —— `proxy.golang.org` 在本机不通(实测超时)。
- PowerShell 侧脚本用 `//go:embed` 编进 exe,exe 可单独拷走。
- 退出码:`0` 成功 · `1` 一般错误 · `2` 用法错误 · `126` 不可执行 · `127` 命令未找到。
- **值保证(不可协商)**:`0xa`→`10`、`STATE: 1`→`Stopped`、`86,488 K`→`86488064`、任何输出**无 ANSI 色码**。
- 输出:① 层严格模仿 bash 文本语义;② 层默认 TSV(列序固定,提供 `--header`);任意命令 `--json` 给类型化 JSON 数组。
- **不认识的 flag 必须报错退出,不得静默忽略。**
- 第一批命令:① 层 `ls` `cat` `grep`;② 层 `reg` `svc` `ps` `sys`。
- 协议:4 字节小端长度 + UTF-8 JSON(与 `pwshx` 一致)。
- 本机环境事实:`bash` 在 PATH 里指向损坏的 WSL relay;Git Bash 在 `C:\Program Files\Git\bin\bash.exe` 但不在 PATH;`pwsh` 在 `C:\Users\Test User\Applications\PowerShell-7\`;Windows 进程创建成本 ~15ms。

## Review Focus

spec 是愿景文档,它没说的地方不等于可以出错。以下是 spec 隐含、但没有任务测试覆盖、且最可能伤到使用者的五类输入。每一行都必须在拥有该代码的任务里配上测试。

1. **含空格与中文的路径** —— 本机的工作目录就是 `D:\work\中文 目录`,用户目录是 `C:\Users\Test User`。任何路径处理都不得截断、不得转义失败。
2. **`grep` 的正则方言差异** —— AI 会写 `grep -E 'a|b'`,而 Go 的 `regexp` 与 POSIX ERE 并非完全一致(例如 `\d`)。差异必须被明确处理,而不是静默给出错误结果。
3. **`--json` 遇到不可序列化的值** —— 文件时间、二进制内容、句柄。必须有确定的字符串表示,不得是 `null`、不得崩溃。
4. **管道里的二进制数据** —— `cat file.zip | wc -c`。① 层不得假定 UTF-8,字节必须原样通过。
5. **daemon 死了或被杀了之后 client 的行为** —— 必须给出明确错误并自行恢复(重拉 daemon),不得挂起等待。
6. **shell 内建语义的静默缺口** —— `mvdan/sh` 在 Windows 上未实现某些 bash 行为,而且**不报错**:
   `printf -v var` 会静默输出 `-v`;`<(cmd)` 会把 `TODO: support process substitution on Windows`
   打到 stdout。这类"看起来成功了"的失败,远比"命令找不到"恶劣,必须被 ④ 层明确拦住。

### Task 1: 项目骨架与 IPC 协议

**Files:**
- Create: `winbash/go.mod`
- Create: `winbash/internal/ipc/ipc.go`
- Test: `winbash/internal/ipc/ipc_test.go`

**Interfaces:**
- Consumes: 无
- Produces:
  - `type Request struct { Op, Script, Cwd string; JSON bool }`(字段带 json tag:`op` `script` `cwd` `json`)
  - `type Response struct { OK bool; Out []byte; Errors []string; Exit int }`(tag:`ok` `out` `errors` `exit`)
    —— **`Out` 必须是 `[]byte`,不能是 `string`**。Go 的 `json.Marshal` 会把 string 里的非法 UTF-8 字节
    静默替换成 U+FFFD;`[]byte` 走 base64 能**原样往返**。这是"二进制不被静默损坏"的实现基础
    (Review Focus 第 4 条),也是本设计"不静默做错事"承诺的一部分。
  - `func WriteMessage(w io.Writer, payload []byte) error` — 写 4 字节小端长度 + payload
  - `func ReadMessage(r io.Reader) ([]byte, error)` — 读同样格式;长度 ≤0 或 >64MiB 时报错
  - `func Encode(req Request) ([]byte, error)` / `func DecodeResponse(b []byte) (Response, error)`

```go
func TestBashSemanticsMatchRealBash(t *testing.T) {
	// 语料取自 pure-bash-bible 的字符串/数组/参数展开章节 —— 社区验证过、AI 真会写的写法。
	// 实测 mvdan/sh v3.14.1 在抽样的 40 条里 38 条一致；这里钉住代表性的，防止升级回归。
	cases := []struct{ script, want string }{
		{`v=/a/b/c; echo ${v##*/}`, "c"},            // basename
		{`v=/a/b/c; echo ${v%/*}`, "/a/b"},          // dirname
		{`v=axbxc; echo ${v//x/-}`, "a-b-c"},        // 全局替换
		{`v=abc; echo ${v^^}`, "ABC"},               // 大写
		{`v=abcdef; echo ${v:1:3}`, "bcd"},          // 子串
		{`v=abc; echo ${#v}`, "3"},                  // 长度
		{`unset v; echo ${v:-def}`, "def"},          // 默认值
		{`a=(1 2 3); echo ${a[@]}`, "1 2 3"},        // 数组
		{`a=(1 2 3 4); echo ${a[@]:1:2}`, "2 3"},    // 数组切片
		{`printf 'a\nb\n' > s.txt; mapfile -t A < s.txt; echo ${#A[@]}`, "2"}, // mapfile
		{`echo {1..3}`, "1 2 3"},                    // 花括号展开
		{`n=v; v=hi; echo ${!n}`, "hi"},             // 间接引用
		{`declare -A m; m[k]=v; echo ${m[k]}`, "v"}, // 关联数组
	}
	for _, c := range cases {
		s := NewSession()
		out, exit, _ := s.Run(context.Background(), c.script)
		if exit != 0 || strings.TrimSpace(out) != c.want {
			t.Errorf("script %q: got %q (exit %d) want %q", c.script, strings.TrimSpace(out), exit, c.want)
		}
	}
}
```

- [ ] **Step 4: 实现 `internal/daemon/daemon.go` 与 `internal/client/client.go`**

**传输层决策(这是与 spec §9 的一处偏差,理由如下,记录下来以免实施者重新纠结):**

spec §9 写的是"命名管道",但 **Go 标准库没有 `CreateNamedPipe` 封装**,而 Global Constraints 限定
"唯一直接依赖 `mvdan/sh`"。手写 `syscall.NewLazyDLL("kernel32.dll")` 去调 `CreateNamedPipeW`
虽然可行,但要自己处理 `PIPE_ACCESS_DUPLEX` / `PIPE_TYPE_BYTE` / 阻塞模式 / `ERROR_PIPE_BUSY` 等细节,
踩坑面大且难测。**改用 TCP loopback:**

- daemon:`net.Listen("tcp", "127.0.0.1:0")` 取随机端口,把端口号写进 `%TEMP%\winbash-<user>.port`
- client:读该文件拿端口,`net.Dial("tcp", addr)`
- 收益:零第三方依赖、纯标准库、本机 loopback 往返延迟与命名管道同级
- 代价:失去命名管道的 ACL 保护(127.0.0.1 仅本机可达,对个人开发工具可接受)

**spec §9 需同步更新。** 本计划其余部分统一用 `endpoint` 指代传输地址。

**约定(测试依赖它)**:daemon 退出时(无论 `--stop` 还是空闲超时)**必须删除端口文件** ——
否则下次启动 client 会读到陈旧端口、连上一个不存在的地址。

client:连不上则 spawn daemon 后重试(最多 20s)。
